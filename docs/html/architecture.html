Architecture Whitepaper

System Architecture & Directory Isolation Matrix

How Agy Account Swarm eliminates credential collisions and enables multi-tenant Antigravity CLI execution.

1. The Multi-Account Concurrency Problem

The official Google Antigravity CLI (agy) is architecturally designed around a single-user model. By default, it persists OAuth refresh tokens, session state, lock files, and conversation databases exclusively within: 

%USERPROFILE%\.gemini\antigravity-cli\

When developers attempt to execute two concurrent instances in separate command prompts on different Google accounts, collisions occur immediately:

Collision Type Default Mechanism Observed Failure
Token Overwrite Single google_accounts.json file Account B login immediately revokes Account A's session in mid-flight.
Lock Contention presence/*.lock and SQLite WAL locks Database locked error (SQLITE_BUSY) causing CLI process crash.
Directory Whitespace Unquoted mkdir C:\Users\user \.gemini The system cannot find the path specified (PathError syscall).

2. Process Sandboxing Architecture

Agy Account Swarm solves this by intercepting and redirecting environment variables before spawning each terminal process. Using ProcessStartInfo with UseShellExecute = false, each child process receives a virtualized root sandbox:

3. Environment Variable Redirection Matrix

Environment Variable Injected Sandbox Target Purpose
USERPROFILE <ProfileDirectory> (Sanitized via .Trim()) Forces CLI to place .gemini/ inside the profile sandbox.
HOME <ProfileDirectory> Ensures cross-platform Go runtime uses the isolated home folder.
APPDATA <ProfileDirectory>\AppData\Roaming Isolates any roaming application caches.
LOCALAPPDATA <ProfileDirectory>\AppData\Local Isolates crash reports and temporary crash dumps.

4. Database Schema (SQLite DDL & DML)

Inside each sandboxed profile's .gemini\antigravity-cli\conversation_summaries.db, SQLite stores session threads: 

-- SQLite DDL Schema Definition
CREATE TABLE IF NOT EXISTS conversation_summaries (
    conversation_id TEXT PRIMARY KEY,
    workspace_path  TEXT NOT NULL,
    summary_text    TEXT,
    model_name      TEXT NOT NULL DEFAULT 'gemini-3.8-flash',
    total_tokens    INTEGER DEFAULT 0,
    created_at_ms   INTEGER NOT NULL,
    updated_at_ms   INTEGER NOT NULL
);

CREATE INDEX IF NOT EXISTS idx_summaries_workspace 
ON conversation_summaries (workspace_path);

CREATE INDEX IF NOT EXISTS idx_summaries_updated 
ON conversation_summaries (updated_at_ms DESC);

-- Real-time Audit DML Query
SELECT 
    conversation_id, 
    workspace_path, 
    model_name, 
    datetime(updated_at_ms / 1000, 'unixepoch', 'localtime') AS last_active
FROM conversation_summaries
ORDER BY updated_at_ms DESC
LIMIT 50;
