Architecture & Feasibility Assessment

Cross-Platform Linux & macOS Architecture

In-depth technical breakdown of WPF Win32 constraints, Avalonia UI migration, POSIX sandbox launchers, and macOS readiness assessment.

1. Technical Reality: Why WPF is Windows-Only

The current Agy CLI Account Swarm application is built on WPF (.NET 9 Windows). WPF has deep hardware and operating system ties that prevent it from running natively on non-Windows platforms:

  • DirectX Pipeline: WPF renders via DirectX 9/11 using the unmanaged Windows Media Integration Layer (milcore.dll).
  • Win32 Message Pump: Relies on native Win32 window handles (HWND), User32.dll, and Gdi32.dll.
  • Native Credential APIs: Integrates with Windows Data Protection API (DPAPI) and Windows Credential Manager.

Consequently, the existing AgyAccountSwarm.exe binary cannot execute on Linux distributions or Apple macOS systems.

2. Honest Assessment: Is macOS Safe & Issue-Free?

Direct Verdict: NO, macOS is NOT currently safe or issue-free.

Running the existing application on macOS without dedicated cross-platform engineering is completely impossible. macOS imposes distinct architectural and security requirements that must be addressed.

Built-in Cross-Platform POSIX Launcher: run-agy.sh

The application already generates an isolated run-agy.sh script in every sandbox alongside run-agy.cmd:

#!/usr/bin/env bash
# AGY Sandbox Shell - Generated by Agy Account Swarm
export USERPROFILE="$HOME/.gemini-profiles/worker-1"
export HOME="$HOME/.gemini-profiles/worker-1"
export ANTIGRAVITY_APP_DATA_DIR="$HOME/.gemini-profiles/worker-1/.gemini/antigravity-cli"
export JETSKI_APP_DATA_DIR="$HOME/.gemini-profiles/worker-1/.gemini/antigravity-cli"
export SSH_CONNECTION=1
export SSH_CLIENT=1
cd "$HOME/workspace" || exit 1
if [ "$1" = "--cli-only" ]; then
    echo "[AGY Sandbox Shell - Profile: Worker 1]"
    exec "${SHELL:-bash}"
else
    exec agy --dangerously-skip-permissions "$@"
fi
