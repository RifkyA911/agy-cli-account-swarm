ARCHITECTURAL ROADMAP SPECIFICATION

Swarm Propagation & Git Worktree Architecture

Deterministic task distribution, parallel workspace branching, and ToS-compliant quota relay across sandboxed Google Antigravity CLI sessions.

1. The Multi-Agent Collaboration Dilemma

When running multiple autonomous CLI agents concurrently on the same codebase, traditional setups inevitably suffer from fatal collisions:

  • Repository Lock Contention: Concurrent git commits or branch checkouts in a shared directory fail immediately due to .git/index.lock locking.
  • Uncoordinated File Overwrites: Multiple agents modifying the same files in a single working tree overwrite each other's edits without review.
  • Disk & Network Waste: Cloning full repository copies for N accounts wastes disk storage and duplicates remote fetch cycles.

2. Git Worktree Integration (The Foundation)

Git Worktree (git worktree) allows a single local repository to support multiple linked working trees simultaneously:

[Repository Core: D:/Projects/MyApp/.git]
   │
   ├── Working Tree 1 (main): D:/Projects/MyApp               ➔ Default Account [Gemini Pro]
   ├── Linked Tree 2 (swarm/worker-a): .../worktrees/worker-a ➔ Worker A [Gemini Flash]
   └── Linked Tree 3 (swarm/worker-b): .../worktrees/worker-b ➔ Worker B [Claude Sonnet]

Shared Object Store

Zero repository duplication. All commits, blobs, and branches share the single .git database. Worktree folders only contain the checked-out files.

Zero Lock Collisions

Each worktree maintains its own independent index file (.git/worktrees/{id}/index). Workers can stage, commit, and edit files without blocking peers.

3. End-to-End Swarm Inflow Pipeline

  1. Task Definition: User selects swarm workers and prompt objectives in the GUI control tower.
  2. Worktree Provisioning: The application automatically executes git worktree add -b swarm/{worker} ../.worktrees/{worker}.
  3. Configuration Propagation: Global rules (GEMINI.md), settings, and MCP servers are propagated to the worker's sandbox directory (~/.gemini-profiles/{id}/).
  4. Context Forking: Past conversation turns and transcripts can be optionally branched to seed the worker with context without contaminating the parent chat database.
  5. Parallel Execution: Sandboxed CLI sessions run in parallel across the distinct worktrees.
  6. Reconciliation & Merge: GUI presents branch diffs for visual review, enabling 1-click merging back into the primary branch.

4. Dynamic Quota Failover Relay

Google Antigravity enforces rolling 5-hour demand smoothers and weekly tier limits. When Worker A exhausts its 5-hour limit:

⚡ Automated Task Handoff

The system allows the current turn to complete gracefully, serializes active turn state, and hands off the worktree and session to Worker B (with fresh quota capacity), continuing automated workflows seamlessly.
